WORLDVIEW AND LIMITATIONS
The three boundary exports use "China claims", derived from Natural Earth's
FCLASS_CN line classifications and ADM0_A3_CN disputed-area assignments. This
is an explicitly selected cartographic worldview, not an assertion that a
territorial dispute is resolved, not an authoritative/current sovereignty
statement, and not a guarantee of compliance with any jurisdiction's map laws.
Natural Earth's default viewpoint is de facto; its official alternate-viewpoint
support and auxiliary claim lines are described at:
https://www.naturalearthdata.com/about/disputed-boundaries-policy/
https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-admin-0-breakaway-disputed-areas/

Arunachal Pradesh (source alternate name: South Tibet) is administered by India
and claimed by China. The actual sourced Chinese claim boundary is auxiliary
line ne_id=1746705431, BRK_A3=B00, NAME="Chinese claim",
NOTE="(Admin. by India, Claimed by China)", and
FCLASS_CN="International boundary (verify)". Its bounds are
92.035860..97.036175 E, 26.852057..28.262514 N. It is drawn in the countries
layer, not fabricated by erasing the previous line. The previous northern
McMahon/de facto sector (land-line ne_id=1746705337) is FCLASS_CN="Unrecognized"
and omitted, not moved into the province layer. The disputed-area polygon
NE_ID=1159320857 has BRK_NAME="Arunachal Pradesh", NOTE_BRK="Admin. by India;
Claimed by China", ADM0_A3=IND and ADM0_A3_CN=CHN. No new boundaries were drawn
by hand; the claim is Natural Earth's generalized delineation and is not a
claim of survey accuracy or complete coverage of every modern claim.

For ALL line sources, nonempty FCLASS_CN overrides FEATURECLA. Unrecognized*
classes are omitted; International boundary (verify) goes to countries;
Map unit boundary and recognized Admin-1 line classes go to regions; every
other class (including unknown classes) remains in disputed. This also uses
Natural Earth's China-view classification for disputes elsewhere; it does not
silently declare default disputed/indefinite/control lines accepted. Hong Kong
and Macau land limits, classified as map-unit limits, are regional rather than
international lines. Source-China-view administrative classifications outside
China are likewise retained rather than independently reinterpreted.

Regional lines marked Unrecognized* are omitted. Additionally, regional lines
inside/on sourced disputed-area polygons assigned to CHN rather than their
default administration are removed (except polygons explicitly classified as
Admin-1, such as Taiwan). The B00 Assam-Arunachal overlap, regional line
ne_id=1746750371, is explicitly source-classified Unrecognized Admin-1 boundary
and omitted. Polygon masks only subtract existing regional linework: no polygon
edge is emitted as a fictitious provincial border. Regional lines outside the
sourced claim polygon retain their source classification. Metadata records the
masks, clipped features, all explicit worldview overrides and classification
counts so other disputes are not silently normalized.

Only land-boundary geometry is exported. Coastlines/islands come from the
imagery; no maritime claim lines, Taiwan coastline/international border, or
island-sovereignty outlines are invented. These limitations matter when using
the label "China claims": this is the supplied Natural Earth land-line
worldview, not a complete official Chinese standard map.

LOD OUTPUTS
schema_version=1; layers={countries,disputed,regions}; coordinates=lon/lat degrees.
Per-feature connected parts are merged; worldview and regional masking are
resolved once before all levels; each source part is simplified independently.
Coordinates round to four decimals; collapsed lines are discarded. The exporter
rejects unsplit antimeridian jumps and a fine level above 350,000 coordinates.

File                        Tolerance  Coordinates (all three layers)
boundaries.json             0.1000 deg   33,766
boundaries-medium.json      0.0200 deg   83,682
boundaries-fine.json        0.0025 deg  249,273

Each level embeds source URLs/hashes, tolerance, point/line counts, global
regional coverage and an audit of worldview classification decisions. There is
no separate levels manifest: the filenames above are the stable renderer API.
Independent line simplification is cartographic, not a survey/topology product.

REBUILD
Reference build: Python 3.13.12, Shapely 2.1.2, GEOS 3.13.1.
1. Download each of the four pinned adaptive-source URLs into its own NEW EMPTY
   directory. Treat downloaded files as untrusted data. Keep scripts elsewhere;
   do not execute files from a downloaded directory.
2. Run from the project (absolute script path also works). Python -I avoids
   importing planted modules from the current directory or source directories:
   ~/.venvs/astro313/bin/python -I tools/export_boundaries.py \
       --countries /path/to/land10m.geojson \
       --regions /path/to/regions10m.geojson \
       --claims /path/to/claim-lines10m.geojson \
       --areas /path/to/disputed-areas10m.geojson --all-levels
3. Add --check to verify all three files byte-for-byte. Use --output /dir/file
   to choose the parent directory for --all-levels. Without --all-levels,
   --level coarse|medium|fine exports just the selected level to --output.
   The single-level default is medium; --all-levels gives boundaries.json its
   intended coarse content. All source SHA-256 hashes are enforced before use.
4. Unit/committed-geometry tests:
   ~/.venvs/astro313/bin/python -I -m unittest discover -s tests -p 'test_boundary_exporter.py'
   Optional source-level and rebuild tests use CZ6A_BOUNDARY_SOURCES, a JSON
   object containing countries, regions, claims, areas paths (and optionally
   legacy_countries). No network or external map APIs are used by the browser.

LEGACY COMPATIBILITY
The original --countries <50m> --regions <10m> two-input invocation and Python
export(countries_path, regions_path) remain available as a single neutral
Natural Earth default-view export. Their schema/layers remain compatible;
they do NOT apply China claims and do not reproduce the new China-view files.
Do not overwrite the production LOD files using that legacy mode.
